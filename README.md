# go-microshop

一个微服务电商后台的骨架，纯标准库，不引框架。包含三块能跑起来的东西：

- **注册中心**：服务启动时注册，定期心跳，超时的实例被清掉
- **网关**：收外部请求，查注册中心找到后端，做限流 + 熔断后转发
- **两个示例服务**：商品服务（增/查）、订单服务（下单，会扣库存算金额）

跑起来就是一套最小的"服务注册发现 + 网关路由 + 容错"链路，能当微服务的教学母本。

## 跑起来

```powershell
go run .
```

会起四个监听：注册中心 :9100、网关 :9101、商品服务 :9102、订单服务 :9103。

通过网关调（路径 `/api/<服务名>/<路径>`）：

```powershell
# 建商品
curl -X POST http://127.0.0.1:9101/api/products `
  -H "Content-Type: application/json" `
  -d '{"name":"键盘","price":99.5,"stock":10}'

# 查商品（把返回的 id 填进去）
curl http://127.0.0.1:9101/api/products/1

# 下单
curl -X POST http://127.0.0.1:9101/api/orders `
  -H "Content-Type: application/json" `
  -d '{"product_id":1,"qty":2}'
```

注册中心自己也能查：

```powershell
curl "http://127.0.0.1:9100/registry/discover?name=products"
```

## 几个关键设计

**服务发现**：网关不写死后端地址，每次转发前问注册中心要健康实例列表，轮询挑一个。后端挂了被 reap 清掉，网关自然就不往那发了。

**限流（令牌桶）**：网关一个桶，每秒补 `rate` 个令牌，桶容量 `burst`。请求来取一个，取不到直接 429。防止突发流量把后端冲垮。

**熔断（circuit breaker）**：每个服务名一个熔断器。连续失败 5 次就"打开"，这段时间内请求直接 503 不转发；冷却 10 秒后放一个探活，成功就恢复，失败继续打开。避免后端已经挂了还持续灌流量引发雪崩。

**订单扣库存**：下单时在商品服务上加锁校验库存、扣减、算金额，一气呵成，库存不足返回 409。练手版没做分布式事务，多实例部署时这把锁只保护单进程内存。

## 没做的事

- 注册中心是单点内存版，没做 Raft 多副本
- 没做认证、没做配置中心、没做链路追踪
- 订单和商品的内存不共享，多实例时数据各自一份

## 测试

```powershell
go test ./...
```

网关转发全链路（建商品→查→下单→库存扣减）、限流是否真拦截、熔断开关、注册中心 TTL 过期清理，都有用例。
